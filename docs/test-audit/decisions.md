# Capability disposition matrix — issue #142

This supplements the baseline source indexes in this directory. Each baseline file and all its declared cases have the group disposition below unless an explicit individual exception in [the main audit](../test-suite-rationalization.md) overrides it. The source indexes contain declarations, source line/blob references, and assertion excerpts; use the source blob for multiline assertions, helper behavior and parameterized variants. The matrix evaluates related groups rather than treating names as proof of equivalence. No individual test was removed merely because its group contains overlapping behavior. Where evidence is insufficient for further consolidation, retain conservatively; these are not mutation-score or exhaustive line-by-line proof claims.

No move to lower layer is justified for the retained interaction/authorization/deployment cases. New regression cases should identify risk and fixture boundary, prefer deterministic lower-level input coverage, extend an existing scenario only where it preserves independent setup and fault signals, and reserve browser coverage for actual cross-boundary behaviors. Name tests by product behavior (not issue number) when new; avoid wholesale renaming. Explicitly classify evaluation-only evidence; do not make screenshots a surrogate for assertions. Do not use retries or arbitrary test reduction targets. Larger evidence and setup review is tracked in #146; APT network reliability in #145.
