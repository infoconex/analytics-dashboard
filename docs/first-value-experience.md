# UX-8 — First-value experience and guided dashboard discovery

## Customer journey

1. On first arrival, the organization and **fictional sample analytics** context remain explicit. A compact “What would you like to understand?” panel offers three concrete sample-data questions: revenue over time, orders by channel, and traffic by channel. Each available question opens an actually matching dashboard; unavailable questions do not link anywhere.
2. On the dashboard list, select a question to find dashboards whose **widget metadata** can answer it. Free-text search intersects the question filter. The result count and “Clear search and questions” action explain and reverse the selection. A no-match state offers **Show all dashboards**; viewers in empty organizations are told that an editor must create a dashboard.
3. A question-selected dashboard identifies its relevant visualization and offers **Go to [visualization]**. The action scrolls the real chart heading into view and focuses it. The chart's “At a glance” description and “View data table” control expose interpretation and exact fictional values; supported date/channel filters can be applied, removed and reset. On dense dashboards, the existing navigation index and “Back to visualization list” preserve a predictable route.
4. **How to explore this dashboard** is collapsed by default and explains filtering, exact values and advanced composition. It is also present in the read-only same-origin UX-6 sample embed; embedding never exposes authoring controls.
5. Browser Back, dashboard list navigation, changing organization and retrying failed authorized list requests provide recovery. Business-question selections are transient UI state, not share links, server data or persisted dashboard edits.

## Engineering decisions and trust boundaries

- `dashboardDiscovery.ts` is a pure matcher over the **active membership’s dashboard list**. It compares the declared sample dataset, metric and dimension (never fuzzy dashboard names), validates `dashboard.organizationId` against the selected membership, chooses an explanatory chart before a metric tile where available, and returns no result for unknown questions or absent charts. No global recommendation data, new backend endpoint, search service, telemetry or external dependency is introduced.
- `DashboardStartingPoints` owns first-arrival presentation; `DashboardTaskGuide` owns the selected chart cue and focus; `DashboardConsumer` owns optional consumer guidance. The existing `DashboardCanvas`, filtering engine, role checks and API contracts continue to own rendering, filter state, navigation and revision-safe writes.
- When the selected organization changes, search, question filter and task selection are cleared. The existing request-generation guard discards late dashboard list responses; only a dashboard returned for the current organization is rendered. No cross-tenant fallback, source activation, or production authentication/embedding protocol is introduced.
- Business questions are intentionally limited to built-in **fictional sample datasets**. The standalone overview summary tiles are also illustrative sample figures and do not establish current customer-specific financial facts. This prototype must not be used for customer decision-making or connected to production data without the separate security and product gates.
- No automatic onboarding tour, modal or editing action is triggered. Viewers and embedded consumers can inspect data but not edit saved dashboard definitions. All authorization still happens on the server; hidden client controls do not constitute an access check.

## Reproducible verification and research separation

- Vitest exercises positive/negative matching, mixed-tenant input rejection, deterministic list results and preference for explanatory charts. Playwright exercises first value, keyword and question search, keyboard/focus, filter/remove, empty/failed/retry, tenant switching, dense return, viewer and embed roles, responsive 1440×900 / 390×844 / 320×900, forced colors and native Chromium 200%/400% tab zoom.
- `web/e2e/discovery.spec.ts` captures full-page responsive/forced-color images, raw Chromium zoom frames and a sample task JSON with outcome, deliberate steps, error list and observed focus. The GitHub Actions Verify artifact is the authoritative browser evidence when a local .NET and Chromium environment is unavailable. Actual run identifiers, counts and limitations must come from completed runs.
- Scripted task completion and focus measurements are **automated evidence only**; no human comprehension, screen-reader spoken output, WCAG 2.2 AA conformance or superiority over Kibana has been established. Preserve the existing proposed 8–12-person Kibana 9.5.6 / Elasticsearch 9.5.6 counterbalanced study and genuine assistive-technology checks as separate evidence gates.
