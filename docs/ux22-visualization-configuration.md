# UX-22 — Persistent chart configuration and visualization authoring

Tracking: [Issue #75](https://github.com/infoconex/analytics-dashboard/issues/75). Branch: `ux22/persistent-visualization-configuration`. Baseline: UX-21 main `c59eebccf2cab3c619dfeadeb35203110a90e2d4`.

## Product decisions

NEXA Analytics Studio is an enterprise-oriented, ultimately embeddable and multi-tenant analytics product. **Simple by default, powerful when needed.** Kibana is design inspiration rather than a required feature match. The current demonstrations use only the original fictional commerce (Jan–Dec, **year unspecified**) and marketing channel rows. No production source, live tenant dataset, inference, goal threshold, conversion model, or new query contract is introduced.

The assessment found nine chart types, previewable authorship, SQLite JSON dashboard persistence, and UX-21 resizable widgets already implemented. Pie/donut leader-line labels were interactive but transient; legend always appeared; histograms were four bins; channel categories lacked sorting; editor controls mixed data and presentation. No duplicate implementations were needed.

## Implemented contract and behavior

| Kind | Optional appearance | Legacy default | Constraints |
| --- | --- | --- | --- |
| Pie / donut | Show category legend, show leader-line labels, max labels | Legend on, labels off, limit 5 | Maximum labels exactly 5/8/12; label count may be less due to share/space |
| Histogram | Number of value-range bins | 4 | 2–12 requested; equal values form a single actual bin; frequency counts original source rows |
| Bar/pie/donut with channels | Category order | Source order | Original order, smallest measure first, largest first; raw data and color identity unchanged |
| Others | No additional appearance overrides | Existing | Chronological month order preserved; no new statistics |

`DashboardWidget.appearance` is an optional record serialized with the existing widget JSON in the catalog, not a migration or a new public integration endpoint. Server-side type/bound checks reject irrelevant/unsupported combinations. Missing settings preserve legacy defaults. The client retains compatible pie/donut settings when switching these kinds, but drops incompatible settings on change of kind or dataset. Widget title/id/layout remain intact. Sorting is limited to marketing channel categorical charts: bar, pie and donut. The supporting source-data table preserves original source order; interactive chart keyboard indices use the displayed category order.

The **Data and measures** panel makes selections explicit; **Appearance (optional)** contains progressively disclosed controls. On sufficiently wide desktop screens, editor settings and an adjacent, sticky live preview remain visible together after scrolling past the visualization gallery; on mobile and high zoom, they stack without horizontal overflow. The preview updates immediately, without changing saved dashboards until **Update visualization / Add to dashboard** followed by dashboard **Save changes**. Cancelling the dialog discards its local edits; cancelling composition discards the dashboard draft. Chart units and axes are described explicitly. Existing consumer-side leader-line label toggles remain temporary, not saved; persistent settings belong to the editor. The same-origin sample embed stays read-only.

## Regression and evidence plan

- NUnit: SQL-backed widget serialization, type and boundary validation, viewer authorization, organization scoping, revision update.
- Vitest: legacy defaults, compatible kind transitions, immutable sorted categories and histogram counts, dashboard dirty detection.
- Playwright: original authoring journey, UX-20 single chart Tab stop and Space selection, labels and legends, add/save/reopen/edit/cancel, sorted-channel keyboard choice, histogram bin counts, screenshot captures at desktop and 390px mobile, plus full existing embed/resizing suite.
- GitHub Actions: Verify (TypeScript, Vitest, NUnit, Playwright and screenshot upload), real SQL Server/PostgreSQL conformance, CodeQL. Evidence artifacts live under the Verify run's `ux-visual-evidence` artifact and `web/test-results/visualizationAuthoring-*/`.
- Screenshot evidence is generated by real Chromium via Playwright, not mocked chart artwork. Any observation about screenshots needs inspection of the resulting CI artifact; a green test alone does not prove visual quality.

## Deferred consolidated manual product-owner review

**Do not request manual review immediately after UX-22.** Once more visualization and dashboard increments are complete, manually review first-use create, edit and change visualization types; chart appearances/behavior, sample data meaning and preview; create/edit dashboards; UX-21 resizing and drag rearrangement; Save, Cancel, browser reload and reopen; embedded read-only behavior; keyboard navigation, focus order and mobile layouts. Capture owner feedback in a later consolidated pass, distinct from automated tests or an independent usability study.

## Security boundaries and future enterprise scope

No changes to authentication or authorization, tenant membership model, organization data isolation, query/provider admission, production embedding, live data source activation, endpoints, tags or releases. Fine-grained user hierarchy and dataset permissions remain distinct architectural work requiring approval. Additional visual features must remain semantically supported by data, rather than incrementing chart counts for Kibana parity.

## UX-23 candidate

Improve creator discovery and organization of visualization/dashboard assets (search/filter and reusable saved visualizations) **without** introducing cross-tenant visibility or public embedding contracts. Assess existing workspace and permission semantics before any UX-23 design.
